# 解析の定義と限界

## 問題点と変更

旧実装の周波数専用FFTにはN要素しかなく、JUCEが要求する2Nの作業領域を満たしていませんでした。複素FFTのインターリーブされた実部・虚部を周波数ごとのMid/Side値として描画し、FFT正規化、窓関数、帯域集計がありませんでした。音声スレッドの書き込み中にGUIが同じ配列を読む構成にもデータ競合がありました。新実装はこの経路をすべて置き換えています。

## スペクトル推定

N=8192、hop=2048（75%重複）、周期的Hann `w[n]=0.5-0.5cos(2πn/N)`。最初の8192サンプルが揃ってから測定します。48 kHzでは窓長170.7 ms、hop42.7 ms、FFTビン間隔5.86 Hzです。追加音声レイテンシーはなく、これらは表示の遅れです。

LとRにそれぞれ実数FFTを行い、2N要素の固定作業領域を使います。複素値 `Lk, Rk` から片側スペクトルのパワーと実クロスパワーを求めます。

```
normalizer = 1 / (N * sum(w[n]^2))
pL[k] = factor * normalizer * |Lk|^2
pR[k] = factor * normalizer * |Rk|^2
c[k]  = factor * normalizer * Re(Lk * conj(Rk))
factor = 2 （Nyquistは1）
```

DCビンは含めません。32の対数帯域は20 Hz〜min(20 kHz, Nyquist)。ビンを周波数幅Δfのセルとして扱い、帯域境界との重なり割合でパワーを配分します。この配分は境界での表示の跳びを減らしますが、低域の分解能を増やしません。帯域幅がビン間隔より小さいと複数の帯域が同じビンの測定を共有します。Hann窓の主ローブも複数ビンに広がります。特に高サンプルレートの最下部は独立した測定ではありません。

窓エネルギーで正規化した帯域パワーを足し合わせると、帯域内の定常信号の平均二乗値を推定できます。振幅0.5の同相1 kHz正弦波で、全帯域の合計は-9.03 dBFSです。これはFFTピーク振幅やLUFSではありません。ノイズは幅の広い高域の帯域に多くのパワーを持ちます。対数帯域内の積分エネルギーなので、白色ノイズが水平になるPSD表示とは異なります。

## 平滑化と指標

帯域ごとのpL・pR・cを、時定数250 msの指数平均 `a=exp(-hop/(sr*0.25))` で平滑化します。最初のフレームはそのまま採用。dBや比率を直接平均しません。

```
P = (pL + pR) / 2
Mid power = (pL + pR + 2c) / 4
Side power = (pL + pR - 2c) / 4
levelDb = 10 log10(P)
Side fraction = Side power / P
correlation = c / sqrt(pL * pR)
balance = (pR - pL) / (pL + pR)
Mono sum relative dB = 10 log10(1 - Side fraction)
```

Side fractionは0〜1、相関とバランスは-1〜+1。丸め誤差を範囲内へクランプします。Pが-90 dBFS以下では非アクティブとして点を隠し、比率を未測定表示にします。片方のパワーが1e-12以下なら相関は定義不可と表示します。Mono sumがほぼ完全消失（Side>0.9999）ならcancellationと表示します。

複素クロススペクトルの実部を使うため、相関は帯域内の平均的な同相・逆相関係を示します。コヒーレンス、位相角、遅延時間、聴感的な幅を直接測るものではありません。90度位相差でも相関0になります。左右でゲイン差があれば、相関+1でもSideは0にはなりません。ミックスされた多数の音源から、個々の音源の位置を復元することもできません。

## 3D表示と視点

Xは対数周波数、YはSide割合、ZはRMSレベル。正規化した表示範囲を中心原点の直方体へ写像し、単位クォータニオンで回転して平行投影します。ドラッグは球面トラックボール、ホイールは表示倍率だけを変えます。倍率を変えても測定値は変わりません。画面内の軸矢印と方向表示は同じ回転を使います。

軸への整列では視線方向の座標が投影から消えます。X方向では周波数、Y方向ではSide、Z方向ではRMSが重なります。Z方向とMapでは、隠れたRMSを点の大きさでも示します。色は全方向で同じ左右相関です。点を奥から手前へ描き、重なった点の選択は近い投影位置と深度で決めます。重なりから個々の音源を分離できるわけではありません。

## スレッドと音声通過（処理経路）

音声スレッドは32,768サンプルの固定容量SPSC FIFOにL/Rをコピーします。動的確保、FFT、GUIアクセス、ミューテックス待機を行いません。Mono入力は解析用に同じチャンネルをL/Rへ複製。入力音声は書き換えず、MIDIもそのままです。NaN/Infは解析コピー内だけで0へ変換します。

解析スレッドは最大2048サンプルずつ取り出し、空なら5 ms待機。GUI用スナップショットのロックを使うのは解析スレッドとGUIだけです。prepareToPlayでは解析スレッドを停止してからFIFO・窓・平均値をリセット。releaseResourcesとデストラクタはスレッドを停止します。

FIFO過負荷ではサンプルを上書きせず、新しい解析入力の一部を破棄。解析側はスキップを検出してキューを読み捨て、連続窓を作り直します。過負荷中の表示は測定を保証しません。音声出力は常にそのままです。ホストが入力コールバック自体を停止した場合は最後の値を保持し、GUIにNO RECENT AUDIOを表示します。
